# 喵舒 · Agent 路由方案 V3（风险分流 + 渐进确认 + 多模态补全）

> 目标：语音输入后，AI 通过**风险分流** → **多轮交互补全疼痛实体** → **渐进确认** → **生成方案** → **疼痛类自动填充到疼痛记录页**。
> V3 在 V2 基础上新增：红旗信号筛查、渐进式确认、可中断恢复、多模态点选补全、异常边界处理。

## 二、核心实体定义

| 实体 | 字段名 | 是否必填 | 示例 | 补全方式 |
| --- | --- | --- | --- | --- |
| 疼痛点位 | `pain_locations` | **必填** | 下腹、腰部 | 语音 + 体图点选 |
| 疼痛强度 | `pain_intensity` | **必填** | 7/10 | 语音 + 0-10 滑块 |
| 疼痛性质 | `pain_type` | **必填** | 绞痛、坠痛 | 语音 + 标签点选 |
| 伴随症状 | `symptoms` | 推荐 | 恶心、乏力 | 语音 + 标签多选 |
| 当前场景 | `scene` | **必填** | 办公室、居家 | 语音 + 标签点选 |
| 疼痛感受 | `pain_feeling` | 推荐 | "像被人拧着" | 语音输入 |

**必填项缺失时**，必须追问至少 1-2 轮；用户仍无回复则继续流程。**推荐项缺失时**，优先追问 1-2 项，用户可说"跳过"跳过，无回复则继续流程。追问过程以弹窗/卡片形式展现，支持语音回复或点选回复。

## 三、方案一：风险分流前置的双通道设计

### 设计
在意图识别后增加**红旗信号快速筛查**节点：

- **若检测到高危特征**：优先进入「就医建议与风险提示」通道，不直接生成舒缓方案。
- **若未检测到高危特征**：进入「记录与舒缓方案」通道。

### 红旗信号关键词（示例）

| 类别 | 关键词/描述 |
| --- | --- |
| 强度 | "10分"、"痛到晕"、"无法忍受"、"想死" |
| 持续时间 | "疼了三天三夜"、"一直痛"、"越来越重" |
| 出血异常 | "大出血"、"血块很多"、"非经期出血" |
| 全身症状 | "发烧"、"呕吐不止"、"晕厥"、"站不起来" |
| 特殊人群 | "怀孕后"、"刚做完手术" |

### 实现
- 在 `classifyIntent` 后调用 `screenRedFlags(text, entities)`
- 命中红旗信号时，返回 `stage='red_flag'`，页面展示风险提示和就医建议
- 仍允许用户继续记录，但明确提示：「你的描述包含需要关注的信号，建议尽快就医咨询」

### 优点
更符合安全优先原则，减少把高风险用户直接导向自我管理的概率。

## 四、方案二：渐进式确认替代一次性确认页

### 设计
在追问过程中，对已抽取的关键实体做**短句回显确认**，例如：

> "我先记下：下腹部疼痛、强度 7 分、绞痛，对吗？"

用户可以通过语音说"对的"/"不对，是隐痛"来即时纠正。

### 实现
- 每轮 `extractEntities` 后，若新增实体，构造 `echoMessage` 回显
- `voice-result` 页面在 collecting 阶段顶部显示：
  - 已收集实体
  - 本轮回显确认文案
  - 继续语音 / 点选修正入口

### 优点
- 减少最后确认页的信息负荷
- 更容易在早期纠正 ASR 或抽取错误

## 五、方案三：可中断与可恢复的对话状态管理

### 设计
允许用户在任意轮次说"先这样"或关闭弹窗，系统：

1. 保留已收集实体到 `consult_session`
2. 允许用户直接生成不完整记录（标记为 `isDraft: true`）
3. 在疼痛记录页提示「信息不完整，可随时补充」
4. 下次进入首页语音入口时，检测到有未完成 session，提示「是否继续补充上次疼痛记录？」

### 会话状态扩展

```javascript
{
  stage: 'collecting' | 'confirming' | 'result' | 'red_flag' | 'interrupted',
  isDraft: boolean,            // 是否为中断草稿
  canResume: boolean,          // 是否可恢复
  resumeHint: string,          // 恢复提示文案
}
```

### 优点
- 更贴合真实使用场景
- 降低放弃率
- 不牺牲数据可用性

## 六、方案四：多模态补全与结构化输入增强

### 设计
在追问弹窗/卡片中，除语音输入外，提供结构化点选入口：

| 实体 | 点选组件 |
| --- | --- |
| 疼痛点位 | 人体示意图点选 |
| 疼痛强度 | 0-10 滑块 |
| 疼痛性质 | 标签：绞痛/坠痛/刺痛/隐痛/钝痛/灼烧痛 |
| 伴随症状 | 多选标签：恶心/呕吐/腹泻/头晕/乏力/腰酸/冷汗/情绪低落 |
| 当前场景 | 标签：居家/办公室/通勤/出差 |

### 实现
- `voice-result` 页面在追问卡片下方展示对应的点选组件
- 用户点选后，直接更新 `consult_session.entities`
- 继续检查缺失实体，进入下一轮

### 优点
- 疼痛状态下，点选比组织语言更省力
- 提升完成率与结构化质量

## 七、异常与边界情况处理

### 7.1 ASR 失败或低置信度

**处理**：
- 提示「没听清，要不要换个说法，或直接点选」
- 同时展开结构化点选入口
- 不强制要求语音

### 7.2 信息矛盾

**场景**：用户先说"持续剧痛"，后说"轻微隐痛"。

**处理**：
- 触发澄清问题：「你刚才说很痛，现在又说轻微，能再确认一下现在的疼痛程度吗？」
- 不直接覆盖，等待用户明确回答

### 7.3 非疼痛意图但含疼痛词

**场景**：用户主要诉求是焦虑或睡眠问题，但提到"心里痛""头痛"等词。

**处理**：
- 意图分类器输出 `has_pain=false`
- 允许用户主动切换意图：「你似乎更想聊情绪/睡眠，要继续走这边吗？」
- 避免强行套入疼痛记录模板

### 7.4 用户中途退出

**处理**：
- 保存 `consult_session` 草稿
- 下次进入时提示：「是否继续补充上次疼痛记录？」
- 用户可选择「继续」或「放弃」

## 十、疼痛记录自动填充 V3

疼痛类方案生成后：

1. 把 `entities` 映射为疼痛记录字段（同 V2）
2. 如果 session 是草稿（`isDraft=true`），记录标记为 `isDraft: true`
3. 保存到本地存储
4. 在记录页展示，草稿记录显示「待补充」标签
5. 支持点击查看 AI 方案和编辑补全
